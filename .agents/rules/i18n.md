# Translations

14 languages, 18 catalogues in `po/`. `locale/` is build output and gitignored;
`install.sh` and `gnome-extensions pack --podir=po` both compile it.

## Workflow for a new or changed string

```bash
npm run i18n:pot && npm run i18n:update   # then fill in every catalogue
npm run i18n:check                        # fails on untranslated or fuzzy
```

Changing a `// Translators:` comment also makes the `.pot` stale, because gettext extracts
those into every catalogue. Same two commands.

## Rules

- **Bind through the extension instance**, `bindTranslations(this)`, not the module-level
  `gettext` exported by `resource:///…/extension.js`. That export resolves the domain by
  walking an `Error` stack for a path under `/gnome-shell/extensions/`; the instance
  methods take the domain from the metadata directly.
- **Use `format()`, never `String.prototype.format`.** That method is not a language
  feature. gnome-shell's `ui/environment.js` installs it, the preferences process does not
  (`typeof ''.format` is `undefined` there), and node does not either, so `.format()`
  anywhere `prefs.js` reaches would throw in that process alone. `format()` also supports
  positional `%1$s`, which fr, tr, ja, ko and zh_CN need to reorder "N of M nodes ready".
- **`N_()` for static tables.** `model.js`'s error headlines and `indicator.js`'s spoken
  severity words are built at module load, before any locale is bound, so they store the
  English source and pass through `_()` at lookup. A table of thunks would also need every
  entry called to satisfy the coverage gate.
- **Never assume two plural forms.** The catalogues run from one (ja, ko, zh) to six (ar).
  Fill every `msgstr[n]` the `Plural-Forms` header declares.
- **Only `%s`, `%d`, `%%` and positional `%1$s`** are understood by `format()`. Leading and
  trailing whitespace must match the msgid exactly. `tests/catalogues.test.js` enforces
  both, plus the column widths the meter and duration labels have to fit.
- **The gschema is deliberately not translated.** Only dconf-editor reads its summaries,
  and it never calls `bindtextdomain()` for this extension's `locale/`, so the entries
  would be unreachable. `po/POTFILES.in` records this.
- **Width is part of the translation.** The menu width is fixed by `.kube-header`. Long
  strings must reflow or ellipsize, never widen the popup.
- **Kubernetes vocabulary stays untranslated**, and so do the `CPU`/`MEM` meter labels,
  which mirror `kubectl top`'s columns. See the wording section in `AGENTS.md`.

Locale fallback behaviour, why 18 catalogues exist for 14 languages, and what has actually
been verified at runtime: `docs/translations.md`.
